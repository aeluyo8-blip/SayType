## P0-1 悬浮球与输入面板应互斥

- **现象**：点悬浮球打开输入面板后，小球仍浮在屏幕上，与面板同时存在，挡视线。
- **复现**：启动悬浮球 → 点球 → 面板出现，球还在。
- **涉及文件**：`android/app/src/main/java/com/phonetype/app/FloatingBubbleService.kt`（`showPanel()`、`togglePanel()`、面板 close 按钮回调、`onDestroy()`）。
- **建议方向**（方案自定，行为要对）：`showPanel()` 成功后隐藏悬浮球 view（`GONE` 或 `removeView`，注意保留触摸状态变量如 `docked`，恢复时要还原）；面板关闭（按钮关闭或 `togglePanel` 收起）时恢复悬浮球显示；服务销毁时两者都已清理。
- **验收**：
  1. 面板打开期间屏幕上看不到球；
  2. 关闭面板球立刻回来，位置/贴边状态不丢；
  3. 反复开关 10 次无泄漏（`dumpsys window` 里 overlay view 数量稳定）、无崩溃；
  4. 面板开着时杀掉服务（通知栏停止），球和面板一起消失。

## P0-1b 悬浮球收起面板后应自动贴边缩小

- **现象**：点开悬浮球 → 输入 → 收起面板后，球停在屏幕中间或原位，不会自动贴边缩小。必须再点一下球、拖动一下，松手靠近边缘才会贴边。
- **预期**：收起面板后若用户没有继续操作，过一小会儿（建议 2s）球应自动飞到最近的屏幕边缘并缩成半透明胶囊（与现有 `dock()` 行为一致）。
- **复现**：启动悬浮球 → 点球打开面板 → 点「收起」→ 观察球停在原地不缩小 → 之后一直不动。
- **涉及文件**：`FloatingBubbleService.kt`（`togglePanel()` 收起分支、`showPanel()` 关闭按钮回调；需要 idle 自动 dock 的 `Handler.postDelayed` / `removeCallbacks`）。
- **建议方向**：
  1. 面板关闭（按钮关闭或 `togglePanel` 收起）时，不立刻 dock，先 `postDelayed(dockNearest, 2000)`；
  2. `ACTION_DOWN` 时 `removeCallbacks` 取消未触发的自动贴边；
  3. 已经贴边（`docked=true`）时不必再调度；
  4. 面板刚关闭时球应恢复完整形态（非 docked），等 idle 后再 dock——避免“收起瞬间就缩走”让用户以为丢了。
- **验收**：
  1. 收起面板后约 2 秒，球自动贴到最近边缘并缩小，无需手动拖动；
  2. 收起后 2 秒内点/拖球 → 取消自动贴边，交互正常；
  3. 反复开关面板 10 次，自动贴边仍工作，无泄漏、无崩溃；
  4. 已贴边态点球打开面板再收起，idle 后仍应贴边（不弹回中间）。

## P0-2 扫码取景页改为竖屏

- **现象**：`MainActivity` 点「扫码配置」后，zxing 取景页在竖屏手机上是横的，手持别扭。
- **原因**：`zxing-android-embedded` 库的 `CaptureActivity` 默认锁横屏（为条形码优化）；现有代码 `ScanOptions.setOrientationLocked(true)` 只是"启用锁定"，锁的方向仍是库默认横屏。我们只扫二维码，竖屏无识别速度损失。
- **涉及文件**：`android/app/src/main/java/com/phonetype/app/MainActivity.kt` 的 `startScan()`。
- **建议方向**：`ScanOptions.setOrientationLock(android.content.pm.ActivityInfo.SCREEN_ORIENTATION_PORTRAIT)`（注意与 `setOrientationLocked(boolean)` 是两个方法）；若该 API 在 4.3.0 不可用，备选方案是在 app 的 `AndroidManifest.xml` 里覆盖声明 `CaptureActivity` 的 `screenOrientation="portrait"`。
- **验收**：竖屏持机取景页为竖屏、提示文案完整显示；扫 PC 端二维码能正确导入配置；按返回取消不崩溃。

## P0-3 启动脚本：端口被占用时引导清理旧进程

- **现象**：电脑上已有 phone-type 服务在跑（或任何程序占了 8787），再双击 `启动服务.bat` 会直接报"端口被占用"退出，小白不知道怎么办；用户有多台手机轮流连的场景，希望重启服务时能一键清掉旧实例。
- **涉及文件**：`scripts/start-service.ps1`（在"启动服务"一步之前加；`启动服务.bat` 是纯入口不用动，注意 PS1 是 UTF-8 BOM）。
- **建议方向**：
  1. `netstat -ano` 过滤 `:8787` 且状态 `LISTENING` 的 PID（只看 LISTENING，避免 TIME_WAIT 干扰）；
  2. 占用时用 `Get-Process -Id` 显示进程名 + PID，`Read-Host` 询问：`检测到 8787 已被 xxx (PID nnnn) 占用，结束它并启动新服务? [Y/N]`；
  3. 输 Y → `taskkill /PID nnnn /F` 后继续正常启动；输 N 或空 → 提示后退出；
  4. 占用进程不是 node 时也要如实显示进程名让用户自己判断（防误杀），但不必禁止 kill。
- **验收**：
  1. 无占用时启动流程与现在完全一致、不多问一句话；
  2. 用 `PHONE_TYPE_PIN=123456 node server/index.mjs` 占住端口后双击 BAT：显示占用信息 → 输 Y → 旧进程被结束、新服务正常起来并打印二维码；
  3. 输 N 时旧进程安然无恙，窗口正常退出。

## P0-4 PC 服务不要占着可见黑窗口

- **现象**：双击 `启动服务.bat` 后会一直有一个黑色控制台窗口。关掉窗口服务就停了；最小化又总在任务栏碍事。用户希望服务能「隐藏式」在后台跑，黑窗口不必常驻桌面。
- **涉及文件**：`启动服务.bat`、`scripts/start-service.ps1`、`server/index.mjs`（横幅/PIN 展示方式可能要配合改）。
- **建议方向**（任选一条能走通的，方案自定）：
  1. **隐藏进程 + 可找回状态**（推荐）：`start-service.ps1` 在自检/装依赖完成后，用 `Start-Process node -WindowStyle Hidden` 拉起服务；PIN/二维码写到日志或状态文件（如 `runtime/last-start.json` / `.txt`），并弹 Windows toast 或短暂显示一个可自动关闭的提示窗口告知 PIN 与「服务已在后台运行」；再提供 `scripts/show-pin.ps1` / `停止服务.bat` 供查看 PIN 与停止服务。
  2. **托盘常驻**：做一个极简托盘图标（PowerShell + WinForms NotifyIcon，或独立小工具），左键显示 PIN/二维码，右键退出。体验最好但工作量大。
  3. **保持控制台但可一键最小化到托盘/后台**：若隐藏方案在打印二维码上有困难，至少做到双击启动后自动最小化，且关窗不直接杀进程（需真正后台化，不能只 `WindowState` 最小化）。
- **约束**：
  - 不要把 PIN 写死；仍随机生成（或尊重 `PHONE_TYPE_PIN`）；
  - 不要在日志里打印用户输入正文；
  - 停止服务的路径要明确（托盘退出 / 停止脚本 / 任务管理器结束 node），文档里写清楚。
- **验收**：
  1. 双击 `启动服务.bat` 后，桌面不残留挡视线的黑窗口（或窗口自动消失/进托盘）；
  2. 手机扫码/手填 PIN 仍能连上并粘贴成功；
  3. 有明确方式再次查看当前 PIN（二次弹窗、托盘、状态文件皆可）；
  4. 有明确方式停止服务，且停止后端口 8787 释放；
  5. 无 Node / 首次装依赖 / 防火墙提权时，错误提示仍然可读（不能变成静默失败）。

## P0-5 主界面：配置完成后自动切到「干净日常态」

- **现象/诉求**：主界面信息太多。配置（IP / 端口 / PIN）做好之后，用户日常只需要：看连没连上、开悬浮球、偶尔改配置。现在三大输入框 + 一堆按钮常驻，显得很吵。
- **预期**：配置完成后主界面**自动变成干净模式**，不是简单「还能看见一大块折叠标题」，而是日常态里默认**看不到**配置表单。
- **两种模式**：

  | 模式 | 进入条件 | 界面内容 |
  |------|----------|----------|
  | **首次/配置态** | 未保存、host/PIN 为空，或用户点了「修改配置」 | 完整配置卡（IP、端口、PIN、扫码）+ 主操作按钮 |
  | **干净日常态** | 已保存且 host/PIN 非空（连接成功后更稳） | 顶部连接状态；主按钮「启动悬浮球」；次操作「连接 PC」；小入口「修改配置」（文字按钮/图标即可）；运行中才有「停止」 |

- **交互要点**：
  1. 满足「已配置」条件时，启动 App **默认进干净态**，不要先闪一下完整表单再收起；
  2. 「修改配置」进入配置态，保存成功后**自动回到干净态**（摘要可显示 `192.168.28.10:8787`，可放状态卡副文案，不要单独占一整卡）；
  3. 配置被清空 / 明显不完整（无 host 或无 PIN）→ 强制回配置态；
  4. 干净态仍要能看出「当前连的是谁」——放在状态卡副标题即可，例如副文案 `192.168.28.10:8787`；
  5. 不要在干净态堆权限、保存、扫码等低频按钮；低频操作收进「修改配置」或状态说明里。
- **涉及文件**：
  - Android：`activity_main.xml`、`MainActivity.kt`（按 Prefs 是否配置完整切换可见性，或两套布局/两组 View 切换）；
  - 原型：`index.html`（先按双模式做原型，用户确认后再动 App）。
- **验收**：
  1. 清数据首启：只有配置态，可填可扫码；
  2. 保存并连接成功后再打开 App：默认干净态，无输入框堆叠；
  3. 干净态点「修改配置」→ 配置态 → 保存成功 → 自动回干净态；
  4. 清空配置后重开：自动回配置态；
  5. 干净态仍能启动悬浮球、连接/停止，不误隐藏主路径。

## P1 讨论过、用户尚未拍板（做之前必须先问用户）

### P1-1 发送文件/图片
可行性已评估过：PC 端 PowerShell 剪贴板支持 `SetImage`（位图）与 `SetFileDropList`（文件列表），手机端需加文件选择器，协议要扩展二进制/分块传输。图片走剪贴板粘贴、文件走资源管理器粘贴。中等工作量（估 2~3 天含真机联调）。用户此前明确说"先不做"，要等用户点头。

### P1-2 UDP 自动发现
局域网内 APP 广播发现 PC 服务，省掉扫码/手填。用户没选过这项。

### P1-3 二维码只编码第一个局域网 IP
`server/index.mjs` 横幅里 `configUri` 用 `addrs[0]`。多网卡（虚拟网卡、WSL 等）时第一个 IP 可能不是手机所在网段，扫码连不上只能手填。可讨论：启动时让用户选 IP、或对每个真实网卡 IP 各打一个二维码。

## P2 工具债

- **P2-1** `test/` 下验证脚本在 Win11 商店版记事本上误报（PowerShell `Start-Process notepad` 阻塞、PID 判定失败）。改用更稳的注入靶（如自己起一个文本框窗口或记事本 win32 版）。
- **P2-2** 工作区有大量未提交改动（二维码、美化、自动重连、小白方案等多个主题混在一起），整理成按主题划分的干净 commit。需用户确认后再动 git。

## 明确不要做的

- 不要把 PIN 写死进代码或提交进 git（安全约束见 `CLAUDE.md`；`PHONE_TYPE_PIN` 环境变量已支持测试场景）。
- 不要添加遥测、上报、自动更新等网络行为。
- 不要把服务改成绑定公网或默认关闭认证。
